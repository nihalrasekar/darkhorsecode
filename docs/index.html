Quick start

From idea to running app in three steps

Pick a model

Open Settings, choose a provider, and paste a key or sign in. No project needs to be open.

Describe the app

On New App, type your idea and choose a build type: Full-stack, Mobile, Landing page or Website.

Watch it build

You land in the Builder. Follow each tool call and the live preview, and send follow-ups.

Fastest free path: Settings → OpenCode → Big Pickle. A free opencode.ai key, no card on file.

Build

Where apps get made

Five tabs cover the whole loop: start a project, build it, reason about its structure, reopen it later, and ship it.

New App

start here

Describe what you want in plain English. This always starts a brand-new project and never reuses the one that is open.

  1. Type your idea, or click a trending prompt to prefill it
  2. Pick a build type. It is folded into the prompt so the agent follows it
  3. Full-stack builds use the Supabase MCP for database, auth and backend
  4. Every build is told to be responsive on desktop, tablet and phone
  5. Hit build to jump straight into the Builder

Builder

The main workspace. Chat with the coding agent, see each read, edit and command as a card, and watch the live preview change.

  1. Send follow-ups in the composer. Your draft survives switching tabs
  2. Tool cards list what the agent read, edited or ran, in order
  3. Stop a run midway if it heads the wrong way
  4. Use the element picker in the preview to point at the exact part to change

Architecture

A system-tree view of the project's logic and structure. It has its own chat, separate from the Builder, so you can talk design without touching the live build.

  1. Discuss changes with the read-only architecture agent
  2. Hand off: it turns the discussion into an implementation plan
  3. The plan goes straight to the Build agent to execute

Projects

Every app you have built, newest first.

  1. Search by project name or file path
  2. Open makes it the active project and shows its details
  3. Delete removes it from the list. Files on disk stay

Deploy

needs a project

Ship the open project through a deployment connector you have added, such as Vercel.

  1. Pick a target. The agent checks the build passes, then deploys
  2. Watch tool output live
  3. Get the live URL when it finishes

Sessions

Every past conversation with your agents for this project, newest first, separate from the main Builder thread.

  1. Click a session to resume where it left off
  2. New starts a fresh session without leaving the tab
Agent Studio

Three built-in agents, plus your own

Each agent has a persona, a model and a set of allowed tools. Create custom ones in Agent Studio and switch them on or off without deleting them.

mode: read · write · run

Build

Edits files and runs commands. This is the agent that actually changes your project.

mode: read-only

Architect

Maps the project as a tree and plans structural changes without editing anything.

mode: read-only

Plan

Proposes an approach for a change before any code is written.

Plan→agree on approach→Build→new session per feature

Talk it through with Plan first, then switch to Build to make the change. Long sessions burn tokens fast, so start a new session for each new feature.

System

Connectors, usage and settings

MCP Connectors

Model Context Protocol servers give agents extra tools: Supabase for Postgres, auth and storage; Vercel for deploys and env vars; Playwright to drive a real browser.

  1. Click a preset. Some need a token, some need no setup
  2. Fill in any required credential and add it
  3. Each server shows Connected, Needs auth, Error or Disabled

Usage

Tokens and cost across every agent run: total tokens, input and output split, cost and agent steps, with a per-day breakdown. It updates live while an agent runs.

Settings

no project needed

Choose your model provider, sign in, and set agent behaviour. It works without a project open, since it is also where you log in.

Agent Studio

Create an agent with a name, persona and system prompt, then choose its model and allowed tools.

Settings → Model

Four ways to power your agents

One provider switcher; the model list changes with it.

OpenCode

free tier

Point it at any OpenAI-compatible endpoint, or use OpenCode Zen, opencode.ai's gateway with several free coding models. Zen needs a free API key with no billing and no card.

Big PickleMiMo-V2.5Ling 3.0 Flash FinNemotron 3 UltraNemotron 3.5 LightningMuse Spark 1.3 Contributor
  1. Settings → Model → click OpenCode
  2. Click a free chip such as Big Pickle. The Zen base URL fills in for you
  3. Get a free key at opencode.ai/auth and paste it under API
  4. Save changes

Anthropic · Claude

API key

Runs Claude models: Opus 5, Sonnet 5, Fable 5.1 and Haiku 4.5. A Claude Pro or Max subscription cannot be used, because Anthropic rejects that login token from third-party apps (401 "API key is invalid"). Get a key from console.anthropic.com.

  1. Settings → Model → click Anthropic (Claude Code)
  2. Paste your key under API
  3. Pick a model. Starred (★) ones are agentic and reasoning-capable
  4. Save changes

ChatGPT · Codex

sign in

No API key. Sign in with your ChatGPT account and run on your existing plan. ChatGPT Go covers three models: gpt-5.5, gpt-5.6-luna and gpt-5.6-terra. The rest of the GPT-5/6 line needs Plus or Pro.

Each model is tagged (Go & Plus/Pro) or (Plus/Pro only). A Plus-only model fails on a Go plan.

  1. Settings → Subscription sign-in → Sign in next to ChatGPT
  2. Log in in the browser window that opens
  3. Set provider to ChatGPT (Codex) and pick a model

Ollama · local

runs on your machine

No key, no cloud, no cost. Models run on your own GPU or CPU. Settings detects your hardware and suggests models that fit your VRAM and RAM, from qwen2.5-coder:7b up to gpt-oss:120b.

  1. Install Ollama and run ollama pull qwen2.5-coder:7b
  2. Settings → Model → click Ollama (local)
  3. Type a model name or click a suggestion (✓ means installed)
  4. Save. Leave Base URL blank for localhost:11434

Data & sign-in

Every agent runs on a local opencode server. DarkHorseCode does not run its own OAuth flow.

About the name

Dark comes from China's dark factories: production lines that run with the lights off and no one on the floor. That is the speed the app chases, agents that build end to end with nobody standing over them. A dark horse is the unexpected one that comes from nowhere and wins. Code is what it does.
